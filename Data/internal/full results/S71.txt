**Abstract.** The objective of this paper is to investigate the use of Support Vector
Regression (SVR) for Web development effort estimation when using a crosscompany data set. Four kernels of SVR were used, linear, polynomial, Gaussian
and sigmoid and two preprocessing strategies of the variables were applied,
namely normalization and logarithmic. The hold-out validation process was
carried out for all the eight configurations using a training set and a validation
set from the Tukutuku data set. Our results suggest that the predictions obtained
with linear kernel applying a logarithmic transformation of variables (LinLog)
are significantly better than those obtained with the other configurations. In
addition, SVR has been compared with the traditional estimation techniques,
such as Manual StepWise Regression, Case-Based Reasoning, and Bayesian
Networks. Our results suggest that SVR with LinLog configuration can provide
significantly superior prediction accuracy than other techniques.

**Keywords:** Effort Estimation, Empirical Web Engineering, Support Vector
Regression.

**1  Introduction**

When planning a software project, estimation of development effort/cost is a critical
management activity, aiming at predicting an accurate effort estimate and at using this
information to allocate resources adequately. Many techniques have been proposed to
estimate the effort necessary to develop a new project. These techniques use data
from past projects, characterized by some cost drivers, to estimate effort for a new
project under development (see e.g., [6], [9]). Thus, the availability of past data
suitable to obtain reliable effort predictions represents a critical issue [15]. Indeed,
software companies may lack their own data set of previously developed projects,
also due to the time required to accumulate enough past data [22][14]. The use of
cross-company data sets, i.e. data sets that contain project data volunteered by several
companies, could overcome this issue. Nevertheless, the application of traditional

estimation techniques, such as Linear Regression and Case-Based Reasoning, may not
provide good results with cross-company data sets [31].

Thus, it is important to investigate new solutions, able to better correlate cost
drivers and development effort in the case of cross-company data sets. In this paper,
we propose to use *Support Vector Regression* (SVR), an approach based on Support
Vector Machines, which are a new generation of Machine Learning algorithms

[40][42]. Our choice is also motivated by the fact that SVR can be easily integrated
with *kernel functions*, allowing the learning mechanism to adapt to different data sets.
To the best of our knowledge, only two previous studies have investigated the
application of SVR for effort estimation, and none of these focused on Web projects
or the use of cross-company data sets. In particular, Oliveira [32] was the first to
apply SVR for effort estimation, exploiting 18 applications from a NASA data set [2],
reporting that SVR significantly outperformed both linear regression and Radial Basis
Function Networks (RBFNs). In the second study, the authors compared various AIbased prediction techniques [4] using two single company data sets: again the results
showed that SVR performed very well.

However, it is widely recognized that the use of cross-company data sets is very
challenging for Software Engineers, and to date there are no studies that investigated
whether SVR is able to deal with the complexity of cross-company data sets in a
significantly superior fashion than other techniques. Moreover, the data sets employed
in the previous studies were characterized by very few independent variables: only
two for the NASA data set, and nine for the second case study.

To overcome this lack of empirical evidence on the effectiveness of SVR in the
field of Web development effort estimation, the contribution of the present paper is to
analyze the application of SVR to a cross-company data set of Web projects, using
data from the Tukutuku database, which has been used in several studies the field of
Web effort estimation [11][21][23][27][31]. Indeed, the Tukutuku database contains
data on 195 Web projects developed worldwide, using different technologies,
methodologies and size. Each project is described by a set of 25 features.

Four kernels for SVR were used, namely linear, polynomial, Gaussian and
sigmoid. Moreover, to reduce the risk that large differences in the variables values,
typical of cross-company data sets, could have unwanted effects on the predictions,
two preprocessing strategies were applied to the variables, namely normalization and
logarithmic transformation. Thus, a total of eight different configurations of the
method were applied.

To evaluate the prediction accuracy of SVR, we carried out for all the
configurations a hold-out protocol, with a training set containing 130 projects
randomly selected from the Tukutuku database, and a test set containing the
remaining 65 projects. As benchmark, we employed Manual StepWise Regression
(MSWR) and Case-Based Reasoning (CBR) due to their frequent use in software
effort estimation studies, Bayesian Networks as used in [22], and the Mean effort and
the Median effort of the data set. Prediction accuracy was measured using the Mean
Magnitude of Relative Error (MMRE) [7], the Median Magnitude of Relative Error
(MdMRE) [7], Prediction at level 25 (Pred(25)) [7], the Mean Magnitude of Relative
Error relative to the Estimate (MEMRE) [17], the Median Magnitude of Relative
Error relative to the Estimate (MdEMRE) [17], boxplots of absolute residuals (actual
effort – estimated effort) and finally boxplots of z (estimated effort / actual effort).

**2  Data Set Description**

In this section the Tukutuku database [24] is described. This database aims to collect
data from completed Web projects, to develop Web cost estimation models and to
benchmark productivity across and within Web Companies [24]. The Tukutuku
database includes information on Web hypermedia systems and Web applications [6].
The former are characterized by the authoring of information using nodes (chunks of
information), links (relations between nodes), anchors, access structures (for navigation)
and its delivery over the Web. Conversely, the latter represents software applications
that depend on the Web or use the Web's infrastructure for execution, and are
characterized by functionality affecting the state of the underlying business logic. Web
applications usually include tools suited to handle persistent data, such as XML files,
(remote) databases, or Web Services. Typical developers are young programmers fresh
from a Computer Science or Software Engineering degree, managed by senior staff.

ASP (VBScript or .Net) in 13.8%, Perl in 11.8%, J2EE in 9.2%, while 9.2% of
the projects used other solutions. The remaining projects used only HTML

**4  Support Vector Regression**

In this section, we present *Support Vector Regression* (SVR) and describe the settings
employed in our case study. SVR is a regression technique based on support vector
machines, a very effective and mathematically well founded machine learning
approach [40][42]. Support vector machines were developed as a nonlinear
generalization of the *Generalized Portrait* algorithm developed in Russia in the sixties

[40] [41], and have been largely developed at AT&T Bell Laboratories in the nineties,
with applications to OCR (Optical Character Recognition), where soon support vector
classifiers became competitive with the other best available techniques [36]. Also in
prediction applications, excellent performances were obtained by support vector
solutions [19].

The large number of applications of support vector approaches to machine learning
tasks are due not only to their performance, but also to the fact that they easily paired
with “kernel functions”, which, as discussed below, allow an actual nonlinear
transformation of the input data space. For the problem at hand, we consider the
application of support vector approach to function estimation, obtaining Support
Vector Regression (SVR). A good introduction to SVR’s mathematical background is
given in a tutorial by Smola and Schölkopf [38], together with some extensions and
implementations and a list of references. Pointers to papers about SVR’s history can
also be found in the references of the cited tutorial.

**Fig. 1.** The soft margin loss setting for a linear SVM [37]

In effort estimation, the input data space has different features for dimensions and
the target function is the effort estimate; both input features and effort estimate are
real numbers. In the version of ε-SVR where no kernel is introduced, we aim at
finding the line which best approximates the training data, but we allow an error no
greater than ε, thus focusing on training points which are farther than ε from the
candidate line. Among all possible solutions, the flattest one is chosen, because this is
usually the optimal choice.

In some cases, it is not possible to find a function satisfying all constraints, and the
introduction of slack variables becomes necessary in order to relax the ε precision
constraint for some of the points. A constant C is introduced to find a tradeoff

Using Support Vector Regression for Web Development Effort Estimation 261

between the flatness of the function and the amount of error introduced by slack
variables. Efficiency reasons suggest the solution of the optimization problem in the
primary or in the dual space depending on whether the number of dimensions is
smaller or larger than the number of training examples. The solution of the dual
problem, with the introduction of Lagrange multipliers, shows how a solution can be
expressed as a linear combination of some of the training examples, namely the
support vectors, and the complexity of the function representation only depends on
their number. Moreover, the introduction of Lagrange multipliers and dual space
solution makes the introduction of kernel functions [37] particularly smooth. Kernels
are very effective to solve the problem in the non-linear case. Indeed, using a kernel
corresponds to a dot product in the feature space, where we apply the linear version of
support vector machines. The literature proposes a large choice of such functions;
some of them are of general application, while others are specific to particular
domains. All of them induce different deformation of the input data space. For our
case study, we applied the four most used kernels, namely *linear*, *polynomial*,
*Gaussian* and *sigmoid* .

The actual application of SVR requires the choice of the values for two sets of
parameters: one regarding the support vector algorithm, including the choice of ε and
C, as discussed above, and a second set regarding the specific kernel adopted. In our
experiments, we have tested various parameter settings.

In our case study, we exploited the *SVM-light* software [18] [1] . This tool takes as input
a text file, contaning a sparse matrix that represents a training dataset of *n* features, and
a set of parameters that allow the user to choose the desidered kernel, ε and C to train an
SVM model. Then, as second step, the tool takes in input a new text file, with a sparse
matrix representing a test dataset with *n* -1 features, and uses it to generate the
predictions for the missing feature, exploiting the previously trained model.

Our results basically confirm the discussion reported in [32], where the best
predictions were obtained with small values of ε (10 [-4] ). We carried out a series of
experiments looking for the best choice of the parameters to use; these are the ones
reported herein.

Another key point of the application of SVR is the normalization of the features.
Indeed, it is worth noting that large differences in the values of the features can have
the unwanted effect of giving greater importance to some of the examples with
respect to the others. This is especially true for the data set we considered, since, as
reported in Table 1, the feature values corresponding to the different projects are very
different in the Tukutuku data set (e.g.: Number of Languages is in a range 1..8, while
Number of Web Pages is in 1..2000]). To avoid such a risk, we considered two
possible strategies: normalization and logarithmic transformation. The former consists
in separately considering each feature vector and divide each of its elements by the
norm of the vector, in order to force all vectors to have norm equal to one.
Logarithmic preprocessing is usually adopted to reduce differences between values:
here we applied it to all the feature values. Of course, once obtained the predictions
by the dataset with the logarithmic transformation, we applied the inverse exponential
function to get the effort in terms of person/hours. This allowed us also to compare in
a uniform way all the gathered results.

kernel and logaritmic transformation of the variables provided significantly better
estimations than all other the other techniques, including MSWR and CBR, that are to
date the most widely and successfully employed prediction techniques in Software
Engineering.

**6  Related Work**

Several studies have been conducted so far to investigate and compare the
effectiveness of techniques like linear regression (LR), stepwise regression (SWR),
CBR, and regression tree (RT), in estimating Web application development effort

[9][11][28]. In such studies some sets of measures have been employed. In particular,
two sets of size measures were used in [9]: the first included some length measures
(e.g., number of Web pages, number of server-side script and applications, etc.) while
the second contained the components used to evaluate the Web Objects measure. The
results reported in [9] revealed that the first set provided better estimates when using
CBR while the second set provided better estimates when using LR [9]. However, the
analysis also suggested that there were no significant differences in the estimations
and the residuals obtained with the two sets of measures. In [11] two prediction
techniques, namely Forward Stepwise Regression (SWR) and CBR were compared
using the following sets of measures: the two sets used in [9], and the Tukutuku
measures [24]. All the measures provided good predictions in terms of MMRE,
MdMRE, and Pred(25) statistics, for both SWR and CBR. The study presented in [28]
employed 37 Web applications developed by academic students while the studies
reported in [9] [11] were based on 15 industrial Web applications.

Recently, Mendes and Mosley investigated the use of Bayesian Networks (BN) for
Web effort estimation using the Web applications in the Tukutuku database [21][25].
In particular, they built eight BNs by exploiting both automatic tools, such as Hugin
and PowerSoft, and a causal graph elicited by a domain expert with parameters
automatically fit using the same training sets used in the automated elicitation (thus
working as composite models ) [7]. As in our study, they exploited the Tukutuku
database of 195 observations and compared the accuracy of the obtained estimates
with those obtained by using Manual SWR (MSWR) and CBR, and median of effort
and mean of effort. That analysis revealed that MSWR provided significantly better
estimations than any of the models using BN and is the only approach that provided
significantly better results than the median effort based model. Furthermore, the
results showed that simpler models, such as the median effort, can provide better
estimates than more complex models, such as those obtained with BN [25]. For these
reasons, in the current study we assessed the SVR performances on the same training
and tests sets, by also comparing them with those obtained by MSWR, CBR, and
mean/median of effort.

On the other hand, only two previous studies have investigated the application of
SVR for effort estimation, and none of these used data from Web projects. In
particular, Oliveira [32] was the first to apply SVR to this field, using data from 18

268 A. Corazza et al.

applications from the well-known NASA software project data set [2]. By using a
leave-one-out cross-validation, the author reported that SVR significantly
outperformed both linear regression and Radial Basis Function Networks (RBFNs), in
terms of the standard indicators MMRE and Pred(25). In the second study, the authors
proposed a method based on machine learning that provides the estimation of the
effort together with a confidence interval for it. In particular, they exploited robust
confidence intervals that are not related to the representation of probability
distributions of the errors in the training set [4]. To assess the defined method, they
performed a case study using the Desharnais [10] and NASA [2] data sets. The results
of this empirical analysis showed that the proposed method was characterized by
better performance with respect to the mentioned study.

However, the authors evaluated the obtained estimations only on the basis of
MMRE and Pred(25), without using other indicators of the goodness of the
predictions [13]. Moreover, they used two single company data sets, characterized by
a very small number of features (only two independent variables for the NASA data
set, namely Lines of Code and development methodology, and nine for the
Desharnais one). It is widely recognized that cross-company data sets are more
challenging for software engineers since they are characterized by different
productivity levels of software companies.

**7  Conclusions and Future Work**

Dealing with effort estimation of new projects is a critical issue for the competitiveness
of software companies, made worse also because of the difficulties of creating own
single-company data sets. In this paper, we have reported our experience in applying a
machine learning-based technique, the Support Vector Regression, to obtain effort
predictions, exploiting a large, cross-company data set of web application, i.e. the
Tukutuku, to date widely adopted for estimation studies in the field of web engineering.

The result we have gathered from this empirical study is that SVR outperforms any
other traditional technique, such as Linear Regression, Case Based Reasoning, and
Bayesian Networks, since it provided significantly superior predictions when dealing
with the considered cross-company data set. In particular, the Linear kernel provided
the best results, after a Logarithmic transformation was applied to the data to
normalize them.

These results confirm the trends observed in [32], and represent a further
contribution to the field by providing evidence of the effectiveness of the SVR
technique also on a much wider, cross-company, Web-oriented data set. Moreover, in
our work the comparison of the prediction accuracy has been carried out using not
only summary measures but also statistical significance tests.

It is worth noting that as with any other real industrial data sets of software or Web
projects, the Tukutuku database does not represent a random sample of projects,
therefore the results presented herein are only applicable to the Web companies that
volunteered data the Tukutuku project and companies that develop similar projects to
those used in this study. Thus, replication of the analysis would be important, as soon
as more data became available.

To further support the project manager in his/her tasks, currently we are working on
the design of a Recommender System embedding SVR, in order to provide a tool that
could automatically choose the best kernel, parameters, and kind of transformation.
Moreover, although in this work we considered four of the most used kernel functions, a
lot more have been proposed and can be considered. The Recommender System based
on SVR could then try each of the kernel functions and different parameter settings to
find out which one has the best performance on the considered data set and then
effectively adapt to the data.
