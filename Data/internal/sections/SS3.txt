I. I NTRODUCTION

The challenge for software cost estimation community is to
build accurate cost estimation models with the following
advantages:

  - Capabilities to adequately model the complex set of
relationship between the effort or cost (the independent
variable) and cost drivers (dependent variables).

  - Capabilities to correctly handle imprecision and
uncertainty. Indeed, most software projects attributes
(cost drivers) are measured by linguistic values such as
‘very low’, ‘complex’, ‘important’ and ‘essential’
which come from human judgments that are always
vague, imprecise and uncertain.

  - Capabilities to learn from historical projects data.

  - Capabilities to be easy to understand and to explain to
users. Otherwise, equivalence or equality must be
established between the model under construction and

an understandable cost model.

To reach these objectives, many techniques have been
developed [1, 2]; most of them are based on a set of artificial
intelligence techniques such as: neural networks [3, 4, 5, 6],
regression trees [7, 8] and case-based reasoning [9, 10, 11, 12,
13, 14]. In this paper, we are concerned with estimation by
analogy, especially an attractive technique referred to as Fuzzy
Analogy [9]. Fuzzy Analogy is based on:

  - *Estimation by analogy*, which is a form of Case-Based
Reasoning [14, 15] based on the following assumption:
*similar software projects have similar costs*, and it has
been deployed as follows. First, each project is



- *Fuzzy logic*, which suggests the use of fuzzy sets rather
than classical sets to represent linguistic values [16]. A
fuzzy set, by contrast to a classical set, is associated
with a membership function, which maps elements in a
real interval (0,1). Thus, a fuzzy set representation
captures the vagueness of one linguistic value by the
use of gradual rather than abrupt-step membership
function.



  - *Linguistic quantifiers*, which are used to evaluate the
similarity between projects when software project
attributes are described by linguistic values [9]. Fuzzy
Analogy uses Regular Increasing Monotone (RIM)
linguistic quantifiers such as ‘ *all* ’, ‘ *most* ’, ‘ *many’*, ‘ *at*
*most* α’ or *‘there exists’* to aggregate the individual
similarities between two projects. The choice of the
appropriate RIM linguistic quantifier, Q, depends on
the characteristics and the needs of each environment.
Q indicates the proportion of individual distances that
we feel is necessary for a good evaluation of the
overall similarity.

Fuzzy Analogy was validated on the COCOMO’81 dataset
that contains 63 historical software projects [9]; each of which
is described by 12 attributes measured on an ordinal scale
composed of six linguistic values: ‘very low’, ‘low’, ‘nominal’,
‘high’, ‘very high’ and ‘extra high’ [17]. The fuzzy
representation (fuzzy sets and their membership functions) of
the 12 COCOMO’81 cost drivers has been empirically
achieved based on their descriptions [18].The results of this
validation were compared to those of the Classical Analogy
approach, ‘fuzzy’ intermediate COCOMO’81 and original
intermediate COCOMO’81. The experiment concluded that
when integrating fuzzy logic in estimation by analogy, the
following results are found:

  - Tolerance of imprecision in software project attributes

  - Improvements of the accuracy of the estimates; Fuzzy

Recently, Fuzzy Analogy was validated using the
International Software Benchmarking Standards Group
(ISBSG) repository [19]. The dataset contains more than 2000
software projects from which 148 projects were retained; each
of which is described by 12 attributes. The results of this
validation showed that Fuzzy Analogy generates accurate
estimates especially when using trapezoidal representation.

In order to approve these promising results, Fuzzy Analogy
must be validated by using various datasets in which software
projects are described either by linguistic or numerical values.
Hence, this paper aims to replicate the above experiments on a
Web software dataset, which contains 53 Web Hypermedia
Applications. Each project is described by 9 numerical
attributes [20]. This objective is reflected in the following
research questions. Using the Web dataset and the experiment
procedure of [9]:

  - Question 1: How accurate is Fuzzy Analogy compared
to Classical Analogy?

  - Question 2: Will Fuzzy Analogy tolerates imprecision
and correctly deals with linguistic values?

  - Question 3: Will Trapezoidal fuzzy representation of
cost drivers generates accurate estimates than
Triangular or Gaussian ones?

  - Question 5: What are the favorable estimation context
of Classical and Fuzzy analogy?

fuzzy representations of the Web software attributes generated
by the FCM-RCGA process. Section 4 presents and discusses
the results of the replication. Finally, conclusions and future
work are given in Section 5.

*A.* *Data Description*

The dataset used in this study represents Web Hypermedia
Applications. The dataset contains 53 Web hypermedia
projects [20]. Each project is described by 9 numerical
attributes, such as the number of html or shtml files used, the
number of media files and team experience (Table 1). Initially,
this dataset contains more than 9 software attributes, but some
of them may be grouped together. For example, we have
grouped together the following three attributes: number of new
Web pages developed by the team, number of Web pages
provided by the customer and the number of Web pages


developed by a third party (outsourced) in one attribute
reflecting the number of Web pages in the application
(Webpages). The use of Fuzzy Analogy on the Web dataset
requires the transformation of numerical values to linguistic
ones. Indeed, the use of linguistic values instead (or in
addition) of numbers serves many major purposes such as
allowance of imprecision and allowance of easy modelinterpretation [22].

*B.* *Evaluation Method*

Two methods were used, in this experiment, to evaluate the
Classical and Fuzzy analogy techniques on the Web dataset:

  - The first method is referred as *jackknife* method, also
called *leave one out cross-validation* . It consists to
derive the estimate for a project by excluding this
project from the dataset; the effort calculation is then
made by using all projects in dataset except the project
under estimation.

  - The second method consists to derive estimate for a
project by considering the project under estimation as
a historical project; the effort calculation is made by
using all projects in dataset. This method is referred to
as All-In method.

The use of Fuzzy Analogy to estimate software
development effort on the Web dataset requires the
determination of fuzzy representations for the attributes
describing software projects. Because the descriptions given of
the Web software attributes are insufficient to empirically build
their fuzzy representations, we suggest the use of an automatic
process to build fuzzy sets and their membership functions. The
proposed fuzzy sets generation process is based on the Fuzzy
C-Means clustering technique (FCM) and a Real Coded
Genetic Algorithm (RCGA). It consists of two main steps (Fig.
1). First, the well-known FCM algorithm and the Xie-Beni
validity criterion are used to decide on the number of clusters
(fuzzy sets) [23, 24]. Second, an RCGA is used to build
membership functions for these fuzzy sets [25, 26].
Membership functions can be trapezoidal, triangular or
Gaussian.

tool developed by the Empirical Software Engineering
Research Group [14]. Hence, we need to configure the
ArchAngel according to the following parameters: similarity

each adaptation strategy, the number of analogies (k) is varied
within the interval [2-5]. Table 3 and Table 4 show the results
obtained when validating Classical Analogy by means of the
two evaluation methods ( jackknife and All-In) on the Web
dataset.

*B.* *Fuzzy Analogy Evaluation*

To generate effort estimates, a quantifier must be specified
beforehand. Normally, for the overall distances, each
environment must define its appropriate quantifier (Q) by
studying its features and its requirements. Because a lack of
knowledge concerning the appropriate quantifier for the
environment from which Web dataset was collected, we used
various α-RIM linguistic quantifiers to combine the individual
similarities. An α-RIM linguistic quantifier is defined by a


fuzzy set in the unit interval with membership function Q given
by:

*Q* ( *r* ) = *r* α α       - 0 (6)

By analyzing the validation results of the Fuzzy Analogy
using both evaluation methods (Tables 5 and 6), we noticed
that the accuracy of the estimates depends on the linguistic
quantifier ( α ) used in the evaluation of the overall similarity
between software projects. So, if we consider the accuracy
measured by Pred(0.20) as a function of α, we can say that, in
general, it increases monotonously according to α (Fig. 4 and
Fig 5). This is because our similarity measures decrease
monotonously according to α . Indeed, when α tends towards
zero, this implies that the overall similarity will take into
account fewer attributes among all those describing Web
software projects. The minimum number of attributes to
consider is one. As a consequence, the overall similarity will be
higher because we are more likely to find at least one attribute
in the Web dataset for which the associated linguistic values
are the same for the two projects. By contrast, when α tends
towards infinity, it implies that the overall similarity will take
into account many attributes among all the available ones
describing the software projects. As a maximum, we may
consider all attributes. Consequently, the overall similarity will
be minor because we are more likely to find one attribute in the
Web dataset for which the associated linguistic values are
different for the two projects.

*C.* *Fuzzy Analogy vs classical Analogy*

When comparing the accuracy of Fuzzy Analogy with that
of Classical Analogy for both evaluation methods, we noticed
that Fuzzy Analogy performs better when � is higher than a
given value, especially when the shape of membership
functions is trapezoidal. Indeed,

 - For the All-In evaluation method, the Classical Analogy
takes into consideration all Web dataset cost drivers and
the best accuracy was obtained when using the IDW
adaptation strategy and three analogies in the adaptation
formula (Pred(20)=80,02%). The Fuzzy Analogy when
using a high value of (>80) also took into consideration
all cost drivers in the evaluation of projects similarity.
However, its accuracy was higher than that of Classical
Analogy (Pred(0.20)=84,91).

 - For the Jackknife evaluation method, the Fuzzy Analogy
performs better in terms of accuracy than the Classical
Analogy (Pred(0.20)=23.15 instead of Pred(0.20)=18.87).
However, the two values of Pred(0.20) still less than the
well-known accepted value of Pred that is around 70%.
This is because the lack of similarities between the
historical projects of the Web dataset.

V. C ONCLUSION

In this paper, we have validated and compared the Fuzzy
Analogy and Classical analogy approaches for estimating the
cost of Web hypermedia applications. The results obtained
approve those found on the COCOMO’81 and ISBSG datasets:
(1) Fuzzy Analogy generates accurate estimates than Classical
Analogy; (2) Fuzzy Analogy tolerate imprecision and
uncertainty when describing cost drivers; (3) Fuzzy Analogy
generates accurate estimates when using Trapezoidal
membership functions rather than Triangular or Gaussian ones;
(4) For both Fuzzy Analogy and Classical Analogy, the
favorable context of their use for a new project is that the
dataset should contains at least one closely similar historical
project to the new project.
